# HVE Studio

正式名称は **Hypervelocity Engineering Studio** です。旧名は EABK Studio です。フォルダーは `EABK-Studio/` から `HVE-Studio/` に、ルートの起動スクリプトは `start-eabk-studio.*` から `start-hve-studio.*` に変わりました。ブラウザーに保存した表示設定は引き続き使えます。

EABK Lite のデータ層（要求定義書・カタログ・System Test の台帳・ID 台帳）を、Product Manager・Architect・Software Engineer の視点で見て回る、ローカル専用の Web アプリです。
EABK を入れた**どのリポジトリでも**動きます（このリポジトリに依存しません）。EABK を使っていない git リポジトリも、コードと PRD から読み取りだけで導出して表示します（下の「EABK なしで使う（コードのモード）」）。UI は日本語・英語を右上の `JA | EN` で切り替えます。

*A local-only web app that lets a product manager explore the EABK Lite data layer (requirements, catalog, system-test ledger, ID registry) of **any** repository with EABK; a git repository without EABK is shown in read-only "code mode", derived from its code and PRD. The UI switches between Japanese and English with the `JA | EN` button.*

> 初めての方は、役割に合うガイドから読んでください: [Product Manager](../users-guide/studio/05-product-manager.md)・[Architect](../users-guide/studio/06-architect.md)・[Software Engineer](../users-guide/studio/07-software-engineer.md)（索引は [users-guide/studio/README.md](../users-guide/studio/README.md)）。各画面が読むデータの一覧は [08-data-reference.md](../users-guide/studio/08-data-reference.md) です。`tools/install.py` で他のリポジトリへ入れると、これらのガイドも一緒に入ります。

## 起動 / Start

Python 3.9 以上で動き、追加 Python パッケージは不要です。Git リポジトリの解析には `git` コマンドが必要です（3D 用の three.js は `web/vendor/` に同梱）。

```powershell
python HVE-Studio/studio.py --repo C:\path\to\your-repo      # ブラウザーが開きます
python HVE-Studio/studio.py --role architect                  # 役割に合う画面から始める
python HVE-Studio/studio.py --check                           # データ層が読めるかだけを確認（起動しない）
.\HVE-Studio\start.ps1 C:\path\to\your-repo -Role pm          # 同じ（Windows）。-Check / -NoOpen も可
./HVE-Studio/start.sh /path/to/your-repo 8765 --role swe      # 同じ（macOS / Linux）。第 3 引数以降は studio.py にそのまま渡す
```

| オプション | 意味 |
|---|---|
| `--repo PATH` | 対象リポジトリ。EABK は不要です。親へたどって最寄りの Git または管理データのルートを使い、入れ子の Git では親の管理データへ移動しません。省略時は、現在のフォルダーにデータ層があるか Git ならそこ、それ以外は Studio 自身のリポジトリです |
| `--port N` | 待ち受けポート（既定 8765。使用中なら次の番号） |
| `--no-open` | ブラウザーを自動で開かない |
| `--role pm\|architect\|swe` | 最初に開く画面（pm = ダッシュボード、architect = マップ（2D）、swe = 表）。画面右上のロールのボタンと同じ |
| `--check` | 管理データのファイルの有無と、解析できた件数・警告を表示して終了（データ層があるか、コードのモードで見られれば 0、どちらでもなければ 1）。コードのモードでは `mode: code (...) requirement-docs=… requirements=… linked-to-code=… code-files=… test-files=… components=…` の行も出ます。サーバーは起動しません |

管理データがなく Git リポジトリでもないフォルダーは、理由を表示して終了コード 1 で終わります。空・文書だけ・バイナリだけの Git リポジトリも開けます。Git のコード解析には `git` コマンドが必要です。

### EABK なしで使う（コードのモード） / Without EABK (code mode)

EABK を入れていない git リポジトリも見られます（FR-1086）。HVE を clone したフォルダーから実行します。

```powershell
python HVE-Studio/studio.py --repo C:\path\to\any-git-repo --check   # mode: code (...) の行で、導出できた件数を確認
python HVE-Studio/studio.py --repo C:\path\to\any-git-repo
```

- データ層があるリポジトリではそれを正本として優先し、ファイル一覧・コードの明示的な要求参照・別の要求文書で補完します。
- データ層がないときは、読み取りだけで次を導出します（何も書き込みません）: Markdown の表の先頭の列と見出しにある要求 ID（`FR-…`・`NFR-…`。`docs/PRD.md` や、名前に prd・requirement・要求・spec を含むファイルを先に読みます）、その ID を書いたコードとテストのファイル（カタログの行の実装ファイル・テストになります）、コンポーネント（共通部品）にまとめたソースのファイル。
- 既存の画面（ダッシュボード・マップ・図式・ソース対応・表）を利用できます。原本にない目的・要求・受入基準・試験合格は推測せず、不足のまま表示します。
- 対象は git リポジトリのルートだけです。ただのフォルダーは走査しません。
- 例: `C:\GitHub\VideoCreator` では `docs/PRD.md` から 103 件の要求、そのうち 56 件がコード・テストにつながり、コードのファイル 78・コンポーネント 6 を表示しました。

画面右上のリポジトリ名を押すと、起動したまま別のリポジトリへ切り替えられます（データ層があるか、コードのモードで見られる git リポジトリ）。データ層のファイルを更新すると、数秒以内に自動で読み直します。
ファイルの場所は、対象リポジトリの `scripts/ebak.config.json`（なければ `scripts/hve.config.json`）の `management_files` に従います。

### リポジトリ分析・タスク管理

ダッシュボードの **リポジトリ分析・タスク管理**（`#/workspace`）から、次を利用できます（FR-1088）。

- Git の追跡済み・未追跡のファイル（初期化済みサブモジュールの中身を含む）の一覧、種別・サイズ・解析状態。ソースだけでなく文書・設定・バイナリのパスも対象です。`packages/` 内のソースも含み、ファイル数による切捨てはありません。Git の無視対象（`.gitignore`）・追跡済みの生成物・依存のディレクトリは「一覧のみ」の行として残し、未初期化・コミット違いのサブモジュールは状態と診断を表示します。
- リモートが GitHub のときは、端末で認証済みの `gh` CLI（`gh auth login`）で Issue・Pull Request・Actions の実行を読み取り専用で取得します（起動時に背景で取得。10 分で再取得、画面の「GitHub から再取得」で即時）。結果はメモリだけに保持し、ディスクには書きません。Issue はタスク一覧に `github:issue:N` として入り、状態の上書きだけを保存します。`gh` がない・未認証・GitHub 以外のリモートのときは理由を表示します。取得件数の上限は環境変数 `HVE_STUDIO_REMOTE_LIMIT`（既定 10000）で、上限に達した種別は「切捨てあり」と表示します。3 種別は並行して取得し、終わった種別から表示します（Actions の実行が多いリポジトリでは CI だけ数分かかります）。1 種別あたりの待ち時間の上限は `HVE_STUDIO_REMOTE_TIMEOUT`（秒、既定 600）で、超えた種別は理由付きで失敗と表示します。`--no-remote` で外部取得を止められます。
- `package.json` と `requirements*.txt` の依存定義、Python・JS/TS の静的なローカル import の関係（マップでも表示）、ローカル参照から到達可能な Git 履歴。コードやテストは実行しません。
- 文書の `- [ ]` / `- [x]`、コードの TODO / FIXME コメントのタスク（ファイル・行付き）、Studio でのタスク作成・題名編集・状態変更・削除。取り込んだタスクの原本は変えず、状態を上書き・リセットします。Studio 作成タスクの削除には確認があります。
- タスクは Windows では `%LOCALAPPDATA%\hve-studio\tasks.sqlite3`、その他では `~/.local/share/hve-studio/tasks.sqlite3` に、リポジトリの正規化した絶対パスごとに保存します。必要なら起動前の環境変数 `HVE_STUDIO_DATA_DIR` で保存ディレクトリを指定できます（対象リポジトリ外を指定）。移動・別 clone は別の対象です。
- コード・文書・設定の変更、追加・削除、Git 参照の変更も自動更新で反映します。タスク作成中の入力は更新・言語切替で維持します。

**取得範囲の注意**: 無視対象・生成物・依存のディレクトリは一覧に残しますが本文は解析しません（無視されたディレクトリは 1 行にまとめます）。認証情報らしいファイル名とシンボリックリンクは本文を読みません。UTF-8 の対応テキストをファイル単位で 1,000,000 バイトまで読み、超過・読取り失敗は一覧と診断に残します。バイナリ・非対応形式はパスとサイズだけです。GitHub 以外のホスティング（GitLab など）の Issue・PR・CI、未初期化サブモジュールの中身は取得しません。「対応範囲と不足情報」でこれらの制約を確認できます。**LLM・Copilot SDK は使用しないため、LLM の料金・予算設定はありません。**

## 画面 / Views

画面上部のナビゲーションは、「何のデータを閲覧できるか」の軸で 9 項目に整理しています。各項目の 1 行説明は、項目にポイントしたときのツールチップと、各画面の冒頭に同じ文で出ます（JA / EN）。分類の軸は、状況の集計（①②）、関係と構造（③④）、データと外部との接点（⑤⑥）、実装との対応（⑦）、元の行（⑧）、保守操作（⑨）です。

| 項目 | 閲覧できるデータ |
|---|---|
| ① ダッシュボード | 目的ごとの進捗・指標・履歴・未解決の件数の集計。要求数・承認率・実装登録率・試験合格率・未回答の質問・BLOCKED、境界ごとの実装。グラフをクリックすると、該当する要求をマップで強調します |
| ② 実装状態 | 承認済みの要求ごとの未着手・実装登録済み・試験 pass 済み（目的別・優先度別・かんばん・一覧表） |
| ③ マップ | 目的 → 要求 → データ・共通部品・API・テーブル → ソースファイル → 試験ケースのつながりをたどる関係のグラフ。**2D / 3D / Graph を切替アイコンで選べます**（2D: 鳥観図からズーム、ツアー、ミニマップ、色の切替。3D: 層にした立体図、ドラッグで回転、ホイールでズーム、ツアー、自動回転。Graph: 関係の図）。。旧「2D マップ」「3D マップ」で、`#/map2d`・`#/map3d` は別名として残ります |
| ④ 図式 | コンテキスト図・目的ツリー・状態遷移図・データ関連図・コンポーネント図・実装配置図（層 × コンポーネント、データ × コンポーネント、置き場、実行環境の見方を含む）。**どの図も 2D / 3D を切替アイコンで選べます**（`#/diagrams?kind=<ctx\|goals\|states\|entities\|components\|layers>&dim=<2d\|3d>`）。旧「配置」の `#/placement` は別名として残り、実装配置図へ移動します |
| ⑤ エンティティ | `#/entities`。行をエンティティ、列を要求と利用シナリオにした対応表（作成・参照・更新・削除を記号と語で表示。絞り込み・並べ替え・CSV・テキスト表示）。見出しを選ぶと `#/entities?entity=<名前>` の詳細（説明・状態と遷移の条件・使う要求・利用シナリオ・管理テーブル・使うコンポーネント／API／共通部品・出典の位置）。エンティティが 0 件のリポジトリでは「エンティティなし」と案内します。導出は `scripts/entities.py` を再利用します。下部の「関係と列（意味的ズーム）」とマップ（関係か列があるとき最初に表示）で、倍率に応じてクラスター → エンティティと関係線 → 列の一覧（型・キー・参照先）に切り替わります（`semzoom.js`・`sz2d.js`・`sz3d.js`。可視範囲だけを描画。`window.eabkView.setScale / getState` を公開） |
| ⑥ 外部連携 | 外部のアプリ・データとの連携（連携先・方向・方式・データ分類）の一覧と詳細。一覧と詳細の表示は FR-1042 で実装します（現在は項目の居場所と案内だけです） |
| ⑦ ソース対応 | カタログに書かれたパスのツリーマップ。ファイルを選ぶと結び付く要求・部品・テスト |
| ⑧ 表 | 元の行を 要求・設計・証跡・運用 の 4 グループの種別で一覧。セルの ID はリンク（未解決 ID は明示）。並べ替え・絞り込み・CSV |
| ⑨ 整合性保守 | 要求正本と違うカタログの題名・決定状態を、プレビュー後に更新（下記）。書込みはここだけ |

`#/structure`（6 つのデータ層の現状と理想の差）と `#/consistency`（要求 → AC → 試験 → カタログ → 実装ファイルの欠け）は、URL で開く ⑨ の補助画面です。

### 2D / 3D の切替

マップと図式の各表示には、切替アイコン（アニメ調の顔つきの「平面」と「立体」の図柄と、「2D」「3D」の語）があります。既定は 2D で、選んだ次元は画面を開いている間だけ保たれます。切替では、選択中の対象・絞り込み・図式の種類・検索の文字が保たれます。キーボード（Tab → Enter）と、検索欄の `> 2D` のコマンドからも切り替えられます。動きの軽減（OS の設定）では、アイコンの動きが止まります。3D を描画できない環境では 2D を表示し、理由と同じ内容の表を示します。アイコンは画面に内蔵した図で、外部から取得しません。

- **検索**: `/` または `Ctrl+K`。結果を選ぶ（Enter）と、開いている図面で関連が強調されます。`Shift+Enter` は結果すべてを強調します。`>` に続けて項目名を入れると、その項目へ移動するコマンドになります。
- **関連の強調**: 図の点にポイントすると直接の関連、クリックすると 2 段先までの関連が強調され、右に詳細が出ます。`Esc` で解除します。
- **リンク**: `http://127.0.0.1:8765/#/map2d?q=<要求ID>`、`#/tables?tab=cases`、`#/diagrams?kind=states&dim=3d`、`#/diagrams?kind=layers&view=runtime` のように画面と検索・タブ・種類・次元を URL で指定できます。旧 URL（`#/map2d`・`#/map3d`・`#/placement?kind=runtime`）も使えます。`?select=<ID>` は撮影用の表示（メニューを隠す）になります。

## 何を読むか / What is read

| 読むもの | 使い道 |
|---|---|
| `docs/requirements-definition.md`（と `docs/requirements/*.md`） | 目的・要求・受入基準・PARAM・用語・状態・ペルソナ・外部連携・質問票・決定記録・監査指摘・出典 |
| `docs/catalog.md` | 機能・共通部品・API・テーブルと、実装ファイル・テストのパス（ソースへの対応はこれだけから作ります） |
| `tests/system/ledger.json` | System Test のケースと結果 |
| `docs/id-registry.md` | ID 台帳の集計 |

Git リポジトリではソースの明示的な要求参照・import・TODO も読み取ります。管理データの定義・承認状態は優先し、コードから新しい要求や試験合格を推測しません。どの画面が何を読むかは [08-data-reference.md](../users-guide/studio/08-data-reference.md) にあります。サーバーは `127.0.0.1` だけで待ち受け、閲覧・検索・CSV 出力・リポジトリ切替で原本を書き換えません。タスクの明示的な編集は上記の Studio 専用保存先だけに書き込みます。

例外は「整合性保守」画面で利用者が差分をプレビューし、`確認して実行` を押した場合だけです。この操作は `docs/catalog.md` の選択した要求行について、`題名` と `決定状態` の2列だけを要求正本へ合わせます。プレビュー後の競合、対象外ファイルへの影響、書込み失敗、`python scripts/verify.py --docs-only` の失敗を検出すると、変更をバイト単位で復元して明示的にエラーを表示します。

## 保守 / Maintenance

- テスト（HVE のリポジトリだけ。`HVE-Studio/tests/` は導入先には入れません）: `python -m pytest HVE-Studio/tests -q`
- 整合性保守: `整合性保守 / Maintenance` → 対象要求 → プレビュー → `確認して実行`
- 構成: `studio.py`（サーバー）、`eabk_model.py`（データ層の読み取りとグラフ化）、`web/`（画面。ビルド不要の ES モジュール。`web/vendor/three.module.min.js` は three.js・MIT）
- 画面の文言は `web/js/i18n.js` の `ja` / `en` に追加します。
