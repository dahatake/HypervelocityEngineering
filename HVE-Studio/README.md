# HVE Studio

正式名称は **Hypervelocity Engineering Studio** です。旧名は EABK Studio です。フォルダーは `EABK-Studio/` から `HVE-Studio/` に、ルートの起動スクリプトは `start-eabk-studio.*` から `start-hve-studio.*` に変わりました。ブラウザーに保存した表示設定は引き続き使えます。

EABK Lite のデータ層（要求定義書・カタログ・System Test の台帳・ID 台帳）を、Product Manager の作業の順番（作業ステップ）に沿って見て回る、ローカル専用の Web アプリです。
EABK を入れた**どのリポジトリでも**動きます（このリポジトリに依存しません）。EABK を使っていない git リポジトリも、コードと PRD から読み取りだけで導出して表示します（下の「EABK なしで使う（コードのモード）」）。UI は日本語・英語を右上の `JA | EN` で切り替えます。

*A local-only web app that lets a product manager explore the EABK Lite data layer (requirements, catalog, system-test ledger, ID registry) of **any** repository with EABK; a git repository without EABK is shown in read-only "code mode", derived from its code and PRD. The UI switches between Japanese and English with the `JA | EN` button.*

> 初めての方は、目的に合うガイドから読んでください: [Product Manager](../users-guide/studio/05-product-manager.md)・[Architect](../users-guide/studio/06-architect.md)・[Software Engineer](../users-guide/studio/07-software-engineer.md)（索引は [users-guide/studio/README.md](../users-guide/studio/README.md)）。各画面が読むデータの一覧は [08-data-reference.md](../users-guide/studio/08-data-reference.md) です。`tools/install.py` で他のリポジトリへ入れると、これらのガイドも一緒に入ります。

## 起動 / Start

Python 3.9 以上で動き、追加 Python パッケージは不要です。Git リポジトリの解析には `git` コマンドが必要です（3D 用の three.js は `web/vendor/` に同梱）。

```powershell
python HVE-Studio/studio.py --repo C:\path\to\your-repo      # ブラウザーが開きます
python HVE-Studio/studio.py --check                           # データ層が読めるかだけを確認（起動しない）
.\HVE-Studio\start.ps1 C:\path\to\your-repo                  # 同じ（Windows）。-Check / -NoOpen も可
./HVE-Studio/start.sh /path/to/your-repo 8765                # 同じ（macOS / Linux）。第 3 引数以降は studio.py にそのまま渡す
```

| オプション | 意味 |
|---|---|
| `--repo PATH` | 対象リポジトリ。EABK は不要です。親へたどって最寄りの Git または管理データのルートを使い、入れ子の Git では親の管理データへ移動しません。省略時は、現在のフォルダーにデータ層があるか Git ならそこ、それ以外は Studio 自身のリポジトリです |
| `--port N` | 待ち受けポート（既定 8765。使用中なら次の番号） |
| `--no-open` | ブラウザーを自動で開かない |
| `--no-remote` | GitHub の Issue・PR・Actions を gh で読まない（INT-002）。生成 AI の設定（INT-003・INT-004）には影響しません |
| `--check` | 管理データのファイルの有無と、解析できた件数・警告を表示して終了（データ層があるか、コードのモードで見られれば 0、どちらでもなければ 1）。コードのモードでは `mode: code (...) requirement-docs=… requirements=… linked-to-code=… code-files=… test-files=… components=…` の行も出ます。サーバーは起動しません |
| `--sync-data` | 表示用管理データを作成・同期し、実際の段階・処理数の進捗を出力して終了。失敗は理由付きで exit 1 |
| `--data-status` | 生成ファイルの有無・絶対パス・同期状態を JSON で出力して終了 |
| `--delete-data` | Studio 所有・内容の整合を確認できる表示用ファイルだけを削除して終了。原本は保持。競合は exit 1 |

管理データがなく Git リポジトリでもないフォルダーは、理由を表示して終了コード 1 で終わります。空・文書だけ・バイナリだけの Git リポジトリも開けます。Git のコード解析には `git` コマンドが必要です。

ブラウザー起動時はスプラッシュ画面に実際の起動段階を表示します。アプリの読込み、ソース・管理データの解析、初期画面の準備に応じて進みます。割合はファイル数や所要時間の推定ではありません。解析失敗時は原因と再試行を表示します。

要求が多いリポジトリでも待てるように、解析中は次のように表示します（FR-1089 AC-497）。
- スプラッシュに、実際の段階（ファイル・関係・履歴・要求の読込みなど）、処理済みの件数、経過時間を毎秒表示します。残り時間の推定は出しません。
- 最初の部分モデル（リポジトリ・読み終えた要求）ができたら、スプラッシュを閉じて画面を表示します。以後は約 5 秒ごと（PARAM-065）に組み立て済みの内容を反映し、完成したモデルに差し替えます。部分表示の間は、画面上部に段階・件数・経過時間のバナーが出ます。
- リポジトリの切替と、原本の更新による読み直しでも同じバナーを表示します。
- 解析の処理時間は要求数にほぼ比例します（例: 要求 160,000 件の生成リポジトリで、サーバー側の解析は約 11 秒）。
- 進捗は `GET /api/model/progress`（`status`・段階・件数・経過ミリ秒・部分モデルの版）、部分モデルは `GET /api/model/partial` で取得できます（ローカル専用・読み取りのみ）。

*While a large repository is analyzed, the splash shows the real phase, counts and elapsed time (no ETA). The screen opens on the first partial model and refreshes about every 5 seconds until the full model replaces it. A banner shows the progress during partial views, repository switches and reloads. Build time scales about linearly with the number of requirements.*
## 作業ステップ・リリース判断・生成 AI・複数のリポジトリ / Work steps, release decision, AI, several repositories

### 作業ステップ（FR-1094）

役割の選択（Product Manager・Architect・Software Engineer）は 2026-11-20 に廃止し（FR-008・FR-1002）、画面上部に Product Manager の作業の順番を 6 つのステップとして並べました。ステップを選ぶと既定の画面が開き、すぐ下の帯に、そのステップの画面（ナビの 9 項目のうち、そのステップの判断に使うものだけ）・判断すること・画面に表示される情報・次のステップが出ます。ステップは矢印キーと Enter、コマンド検索（`>ステップ`）でも選べます。旧 URL や検索結果から画面を直接開くと、その画面が属するステップが選ばれます。

| ステップ | 判断すること | 既定の画面 | ステップ内の画面 |
|---|---|---|---|
| 1 全体を把握する | 目的ごとの進み具合と、どこに手を打つか | ダッシュボード | — |
| 2 要求を固める | 未回答の質問・承認待ち・BLOCKED の解消 | 表（要求） | エンティティ、外部連携 |
| 3 影響を確かめる | 変更がどのデータ・部品・API・コード・リポジトリに及ぶか | ソースコード構造（関数同士の関係性を見る） | マップ、図式 |
| 4 進捗を追う | 実装の登録と試験の pass の進み具合 | 実装状態 | 表（試験ケース） |
| 5 リリースを判断する | 目的が達成されたか、出してよいか | 実装状態の「リリース判断」 | 表（試験ケース） |
| 6 整えて記録する | カタログ・台帳の不整合を直し、決定を残す | 整合性保守 | 表（決定記録） |

### リリース判断（FR-1095）

実装状態の項目の「リリース判断」タブ（`#/release`。ナビの 9 項目は増やしません）に、目的ごとの達成判定（達成・未達・未判定）と、全体の状態（要対応・正常・不明）を、理由・判定に使った台帳の最終実行日時・モデルの測定時刻・要対応の項目の一覧とともに表示します。判定はサーバーの `HVE-Studio/release.py` が管理データだけから行います。管理データを読めない・台帳がない・目的が 0 件・判定対象のない目的がある、のどれかでは「不明」で、「正常」とは示しません。全体の状態はステップ 5 の名前の横に常に出ます。

### 生成 AI（任意。FR-1096〜FR-1098、NFR-SEC-024、NFR-UX-019）

帯の「AI の設定」で、使うかどうかと提供元・認証方式を選びます。選んだ組み合わせに必要な入力欄だけが出ます。

| 提供元 | 認証方式 | 入力・選択 | 必要なもの |
|---|---|---|---|
| Microsoft Azure | Key | エンドポイント、デプロイ名、キー | Azure OpenAI（Microsoft Foundry）のリソース |
| Microsoft Azure | Entra ID | サブスクリプション → リソース → デプロイを一覧から選ぶ | Azure CLI（`az login` 済み）、推論の役割（Cognitive Services OpenAI User など） |
| GitHub Copilot SDK | GitHub CLI のサインイン | モデル | GitHub CLI（`gh auth login` 済み）、`pip install microsoft-copilot-sdk`（Python 3.11 以上）、GitHub Copilot の契約 |
| GitHub Copilot SDK | Key（BYOK） | 接続先の種類、エンドポイント、キー、モデル | `pip install microsoft-copilot-sdk` |

- AI を設定しない・「AI を使わない」を選んだ間は、AI の提供元・Azure Resource Manager・GitHub Copilot へは一切通信しません。必要な部品が足りないときは、不足と導入手順を示すだけで自動では導入しません。
- キーは「保存」で OS の資格情報の保管庫（Windows の資格情報マネージャー、macOS のキーチェーン、Linux の Secret Service〔`secret-tool`〕）にだけ保存し、「キーを削除」で消せます。保管庫を使えない環境では「このセッションだけ使う」（Studio を終了すると消える）を選べます。キーは画面・応答・ログ・ブラウザーの保存先に出ません。gh のトークンは呼出しのたびに `gh auth token` で取得し、SDK へ明示的に渡します（保存しません）。
- 「AI に聞く」は、リポジトリごとに最初の送信の前に、送る情報（ID・題名・状態・受入基準の文・質問票の文・件数・リポジトリ名）と送り先を示して同意を求めます。コードファイルの内容・ファイルのパス・Issue と PR の本文・キーは送りません。回答には「AI 生成（派生物）」・時刻・提供元とモデルが付き、モデルにない ID は「未確認の ID」、選択肢にない推奨は「推奨できない」と示します。「この回答の根拠」に、使ったステップ・送った情報の種類・参照した ID の Studio 上の状態と、送った内容そのものが出ます。Copilot SDK はツールをすべて無効にして呼び出し、AI は管理データ・コードを書き換えません。1 回の応答の待ち時間の上限は 60 秒（PARAM-068）です。

- **月の費用の上限（FR-1101）**: AI の設定に、月の上限（円。既定 100,000 円。PARAM-070）と、入力・出力の単価（円 / 100 万トークン）の欄があります。単価は提供元・モデルごとに違い、Studio は調べないため、入力してください（未入力の間は送信しません）。回答ごとに、提供元が返したトークン数（返さないときは 4 文字 = 1 トークンの概算で「概算」と表示）から費用を概算し、今月の積算（この端末・このブラウザーの分だけ。月・トークン数・円の合計だけを保存し、質問や回答は保存しません）を上限に対する割合で示します。80% で警告、100% で送信を止めます。

### 複数のリポジトリ（FR-1099・FR-1100）

ヘッダーのリポジトリのボタンの横の「＋」で、OS のフォルダー選択からリポジトリを 1 つずつ追加します（最大 10 個。PARAM-069）。一覧のボタンで、名前・パス・表示の方式・読込みの状態と、削除・再試行を表示します。複数のときは ID の前にリポジトリ名が付き（例: `api:FR-001`）、同じ ID も混ざりません。リリース判断はリポジトリごとと全体で示します。選んだパスの一覧だけをブラウザーに保存し、次回の起動で戻します。従来の「リポジトリのボタン」（FR-010）は、全体を 1 つのリポジトリに置き換えます。

ソース対応の「リポジトリ間の関係」タブ（`#/xrepo`）は、各リポジトリのコードから決定的に読み取った関係（コードは実行せず、外部へ通信しません）を図と表で示します。確定: パッケージの依存（宣言した名前の一致）、そのパッケージの import を通した関数の呼出し、HTTP の呼出し（メソッドとパスが一致するエンドポイントを持つリポジトリが 1 つだけのとき）。候補: 一致するエンドポイントが複数あるときの HTTP の呼出し、テーブル名（一方の `CREATE TABLE` と他方の参照）・メッセージのトピック/キュー名・データファイルのパスの名前だけの一致。候補は既定では図に出さず、出すときは破線と「候補」の語で区別します。

### 表示用管理データの作成・同期・削除 / Display data

全画面の上部に、生成ファイルの有無・絶対パス・同期状態と **作成・同期／削除** を常設表示します。処理中は実際の段階と処理済み数／対象数の進捗バーが出ます。削除は対象パスを確認して実行します。

```powershell
python HVE-Studio/studio.py --repo C:\path\to\your-repo --sync-data
python HVE-Studio/studio.py --repo C:\path\to\your-repo --data-status
python HVE-Studio/studio.py --repo C:\path\to\your-repo --delete-data
```

- 保存先は対象の `.hve-studio/managed-data.json`。既存の要求文書・ソース・テストなどの解析結果で、**EABK の要求正本や合格した試験の自動作成ではありません**。原本・隣接ファイルは変更・削除しません。
- `tools/install.py` の実際の導入・更新の最後にも、進捗を表示して同期します。`--skip-verify`・`--no-repair` でも同期し、`--dry-run`・`--check` は作成しません。同期失敗は exit 1 で知らせ、導入済み toolkit は残します。
- 起動・閲覧・リポジトリ切替だけでは作成しません。参照だけの対象には、Studio をそのリポジトリへインストールせず、外から `--repo` で指定できます。
- 原本が変われば「再同期が必要」と表示し、古い生成データでなく現在の原本を表示します。削除後も閲覧を続けられます。GitHub の取得結果と Studio 側のタスク編集は生成ファイルに含めません。
- 外来・編集済みのファイルやリンクは上書き・削除せず、理由を表示します。中断後の `.hve-studio/.operation-lock` が残った場合は、他の同期が動作していないことと内容を確認してから、そのロックだけを手動で除いて再試行してください。

*Installation and explicit CLI/UI actions create a disposable `.hve-studio/managed-data.json` snapshot with real progress. The global banner always shows its presence, path and state. Delete removes only an intact Studio-owned snapshot, not requirements or code; browsing continues from live sources. Viewing alone creates nothing. This is not a migration into approved EABK requirements.*

### EABK なしで使う（コードのモード） / Without EABK (code mode)

EABK を入れていない git リポジトリも見られます（FR-1086）。HVE を clone したフォルダーから実行します。

```powershell
python HVE-Studio/studio.py --repo C:\path\to\any-git-repo --check   # mode: code (...) の行で、導出できた件数を確認
python HVE-Studio/studio.py --repo C:\path\to\any-git-repo
```

- データ層があるリポジトリではそれを正本として優先し、ファイル一覧・コードの明示的な要求参照・別の要求文書で補完します。
- データ層がないときは、読み取りだけで次を導出します（何も書き込みません）: Markdown の表の先頭の列と見出しにある要求 ID（`FR-…`・`NFR-…`。`FR-01` のように桁の少ない番号も含みます。先頭の列名に ID を含み、要求・要件・ストーリー・優先度のどれかの列がある表の行と、`- **SEC-01（Must）**：…` のように ID の直後の括弧に優先度を書いた太字の書き出しでは、`UX-01`・`DEP-01` のような他の接頭辞も要求 ID にします。`docs/PRD.md` や、名前に prd・requirement・要求・spec を含むファイルを先に読みます。git で追跡された `work/` の中のそのような名前の文書も読みます）、その ID を書いたコードとテストのファイル（カタログの行の実装ファイル・テストになります）、コンポーネント（共通部品）にまとめたソースのファイル。
- 受入基準は、要求の下の `受入基準 AC-…:` の箇条書きのほか、先頭の列が `AC`・`ID` で `AC-…` の値を持ち、名前に「要求」を含む列がある表（例: `| ID | 対応要求 | 合格条件 |`）からも読みます（AC-494）。
- 既存の画面（ダッシュボード・マップ・図式・ソースコード構造・表）を利用できます。原本にない目的・要求・受入基準・試験合格は推測せず、不足のまま表示します。
- 対象は git リポジトリのルートだけです。ただのフォルダーは走査しません。
- 例: `C:\GitHub\VideoCreator` では `docs/PRD.md` から 103 件の要求、そのうち 56 件がコード・テストにつながり、コードのファイル 78・コンポーネント 6 を表示しました。

画面右上のリポジトリ名を押すと、起動したまま別のリポジトリへ切り替えられます（データ層があるか、コードのモードで見られる git リポジトリ）。データ層のファイルを更新すると、数秒以内に自動で読み直します。
ファイルの場所は、対象リポジトリの `scripts/ebak.config.json`（なければ `scripts/hve.config.json`）の `management_files` に従います。

### リポジトリ分析・タスク管理

ダッシュボードの **リポジトリ分析・タスク管理**（`#/workspace`）から、次を利用できます（FR-1088）。

- Git の追跡済み・未追跡のファイル（初期化済みサブモジュールの中身を含む）の一覧、種別・サイズ・解析状態。ソースだけでなく文書・設定・バイナリのパスも対象です。`packages/` 内のソースも含み、ファイル数による切捨てはありません。Git の無視対象（`.gitignore`）・追跡済みの生成物・依存のディレクトリは「一覧のみ」の行として残し、未初期化・コミット違いのサブモジュールは状態と診断を表示します。
- リモートが GitHub のときは、端末で認証済みの `gh` CLI（`gh auth login`）で Issue・Pull Request・Actions の実行を読み取り専用で取得します（起動時に背景で取得。10 分で再取得、画面の「GitHub から再取得」で即時）。結果はメモリだけに保持し、ディスクには書きません。Issue はタスク一覧に `github:issue:N` として入り、状態の上書きだけを保存します。`gh` がない・未認証・GitHub 以外のリモートのときは理由を表示します。取得件数の上限は環境変数 `HVE_STUDIO_REMOTE_LIMIT`（既定 10000）で、上限に達した種別は「切捨てあり」と表示します。3 種別は並行して取得し、終わった種別から表示します（Actions の実行が多いリポジトリでは CI だけ数分かかります）。1 種別あたりの待ち時間の上限は `HVE_STUDIO_REMOTE_TIMEOUT`（秒、既定 600）で、超えた種別は理由付きで失敗と表示します。`--no-remote` で外部取得を止められます。
- `package.json` と `requirements*.txt` の依存定義、Python・JS/TS の静的なローカル import の関係（マップでも表示）、ローカル参照から到達可能な Git 履歴。コードやテストは実行しません。
- 文書の `- [ ]` / `- [x]`、コードの TODO / FIXME コメントのタスク（ファイル・行付き）、Studio でのタスク作成・題名編集・状態変更・削除。取り込んだタスクの原本は変えず、状態を上書き・リセットします。Studio 作成タスクの削除には確認があります。

### 2D / 3D の切替

マップと図式の各表示には、切替アイコン（アニメ調の顔つきの「平面」と「立体」の図柄と、「2D」「3D」の語）があります。既定は 2D で、選んだ次元は画面を開いている間だけ保たれます。切替では、選択中の対象・絞り込み・図式の種類・検索の文字が保たれます。キーボード（Tab → Enter）と、検索欄の `> 2D` のコマンドからも切り替えられます。動きの軽減（OS の設定）では、アイコンの動きが止まります。3D を描画できない環境では 2D を表示し、理由と同じ内容の表を示します。アイコンは画面に内蔵した図で、外部から取得しません。

- **検索**: `/` または `Ctrl+K`。結果を選ぶ（Enter）と、開いている図面で関連が強調されます。`Shift+Enter` は結果すべてを強調します。`>` に続けて項目名を入れると、その項目へ移動するコマンドになります。
- **関連の強調**: 図の点にポイントすると直接の関連、クリックすると 2 段先までの関連が強調され、右に詳細が出ます。`Esc` で解除します。
- **リンク**: `http://127.0.0.1:8765/#/map2d?q=<要求ID>`、`#/tables?tab=cases`、`#/diagrams?kind=states&dim=3d`、`#/diagrams?kind=layers&view=runtime` のように画面と検索・タブ・種類・次元を URL で指定できます。旧 URL（`#/map2d`・`#/map3d`・`#/placement?kind=runtime`）も使えます。`?select=<ID>` は撮影用の表示（メニューを隠す）になります。

Git リポジトリではソースの明示的な要求参照・import・TODO も読み取ります。管理データの定義・承認状態は優先し、コードから新しい要求や試験合格を推測しません。どの画面が何を読むかは [08-data-reference.md](../users-guide/studio/08-data-reference.md) にあります。サーバーは `127.0.0.1` だけで待ち受け、閲覧・検索・CSV 出力・リポジトリ切替で原本を書き換えません。タスクの明示的な編集は上記の Studio 専用保存先だけに書き込みます。

原本への書込みの例外は「整合性保守」画面で利用者が差分をプレビューし、`確認して実行` を押した場合だけです。この操作は `docs/catalog.md` の選択した要求行について、`題名` と `決定状態` の2列だけを要求正本へ合わせます。プレビュー後の競合、対象外ファイルへの影響、書込み失敗、`python scripts/verify.py --docs-only` の失敗を検出すると、変更をバイト単位で復元して明示的にエラーを表示します。表示用管理データの明示的な作成・同期・削除は、原本とは別の生成ファイルだけを操作します。
