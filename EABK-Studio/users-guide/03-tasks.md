# 3. こんなとき、どう見るか

## 進み具合を報告したい
1. ダッシュボードの「承認済み」「実装登録」「試験合格」を見ます。
2. 「目的ごとの実装進捗」で、どの目的が遅れているかを確認します。
3. 2D マップで色を「実装状況」にします。赤い点が、まだ実装が登録されていない要求です。

> 「実装登録」は、カタログに実装ファイルが書かれているかどうかです。動作の保証ではありません。動作は「試験合格」と、表の「試験ケース」で確認します。

## ある機能の要求と、どこに作られたかを知りたい
1. 検索欄に機能名や要求 ID（例: `FR-011`）を入れ、結果を選びます。
2. 右の詳細で、本文・受入基準・実装ファイル・テストを見ます。
3. 2D または 3D マップで、そこから伸びる線をたどり、どのコンポーネントにあるかを見ます。

## 目的（ゴール）が本当に満たされているか確かめたい
目的ツリー（図式）で、目的ごとの要求の色を見ます。目的をクリックすると、詳細に成功指標と測定方法が出ます。要求の受入基準の検証レベルは、ダッシュボードの「受入基準の検証レベル」で分かります。

## 「止まっているもの」を洗い出したい
- ダッシュボードの「BLOCKED の要求」をクリック → 地図で強調されます。
- 表の「質問票」で、状態が「未回答」の質問を絞り込みます。答えが決まると、止まっている要求を進められます（回答は EABK のエージェントへ依頼します）。
- 表の「監査指摘」で、未解決の指摘を確認します。

## 承認待ち（AI 提案）を確認したい
表の「要求」で、「決定状態」を「AI提案」に絞り込みます。決定を依頼するときの対象一覧になります。

## ある変更が、どこに影響するか知りたい
変更したい要求を選び、3D マップで関連を見ます。同じデータ（エンティティ）を扱う要求や、同じ共通部品を使う要求が、強調されて見えます。「配置」の「データ × コンポーネント」では、そのデータを扱う実装がどのコンポーネントにあるかが分かります。

## 使っているデータ・API・部品がどこにあるか知りたい
「配置」画面の 3 つのタブを順に見ます。API とテーブルは、カタログに登録されているものだけが出ます（登録がなければ「なし」）。

## 外部の関係者に説明したい
「図式」のコンテキスト図（誰が使い、何と連携するか）と、状態遷移図（業務の流れの状態）を見せながら説明すると、伝わりやすくなります。3D マップの「ツアー」は、全体像を見せる場面に向きます。

## 仕様書に貼る資料がほしい
表の画面の「CSV」で一覧を書き出せます。図はブラウザーのスクリーンショット機能などで保存してください。

## 同じ画面を人に共有したい
アドレス欄の URL を伝えます（同じリポジトリを開いている人のみ）。例: `#/map2d?select=FR-001`、`#/tables?tab=questions`、`#/diagrams?kind=states`。
