用途: HVE-History/20261003-HVEv2-Born.html（フル版 約16分 ＋ SHORT 版 約5分）を、同じ品質で再生成・更新するための Prompt です。 使い方: この全文を Coding Agent（Copilot CLI / VS Code Agent）に渡し、リポジトリーのルートで実行します。 前提: 実行者は HVE-History/ の調査レポート群を読めること。Python（Playwright・Pillow）と Node.js が使えると、検証まで自動で行えます。

1. 役割と目的

あなたは、プレゼンテーション演出と Web フロントエンドに詳しい、シニアのクリエイティブ・エンジニアです。 次の目的で、開くだけで全編が自動再生される、単一の HTML ファイルを作成してください。

  • 題材: Hypervelocity Engineering（HVE）の 262 日（2026-01-23 〜 2026-10-13）の、挑戦・失敗・学び。
  • 聴衆: CIO / CTO と、Lead Software Engineer。
  • 伝えたい主旋律（すべてのシーンがこれに従うこと）: 1. HVE の目的は「業務要件の整理から、設計・実装・検証までを、再現可能なワークフローとして運用する」ことだった。 2. その目的を 7つの目標（後述）に分解し、目標ごとに「何に挑み、何がうまくいき、何がうまくいかなかったか」 を同じ型で示す。 3. モデルと GitHub Copilot Coding Agent が強くなるほど、Prompt・人の介在・自作の仕組みは、より小さくても結果を出せるようになった。当時の足場の多くは不要になり、「能力に依存しない足場」だけが残った。 4. 問い「足場は、いつまで必要か？」に、「測って、外す」と答える。 5. 最後は、コードの Vibe Coding を、事業構想（Business Envisioning）へ向ける。事業 → コード → 事業、と一周する。
  • エンタメ性: YouTube / TikTok / ゲーム実況 / TV 番組の演出（テロップ、SE、ズーム、スタンプ、カウントダウン、コメント流し、どんでん返し）を取り入れ、「次世代の Software Engineering は楽しい」と感じさせる。ただし事実の正確さを損なわないこと。

4. 厳守する制約

  • 金額を載せない。AI の使用量は「AI クレジット（AIU）の数」だけで書く。USD・円・ドルの記載は不可（モデルが変わると変わるため）。
  • 数字・主張には、必要に応じて 事実／推論／未検証 の区別と留保を付ける。特に次は画面に明記する。
  • 「254 回 → 5 回」は条件の異なる参考値（n=1。② は前版の要求・コードの 92% を引き継いだ）。
  • BAS の「1 件 3〜6 分」は目標であり未実測。BAS の画面はデモ（お手本パック）。BAS の要求 144／受入基準 236／System Test 141 は規模の記録で、効果は未取得。
  • Work IQ の 35 問は、情報がテナントに存在しない可能性もあり、方式だけが原因とは断定しない。
  • 「HVE v2 ＝ EABK」は、このストーリーでの置き方。
  • 足場メーター・時間と力のグラフは概念図（実測ではない）。
  • 限界: n=1、EABK は自作、試行 1〜6 回、記録は下限値、モデル進化と足場の効果は分離できない。
  • 「HVE は失敗だった」と言わない。主旋律は「当時の合理的な判断を、測って外した」。判定は誇張せず、解けていない目標（Q7）は正直に NOT YET と示す。
  • 顧客名・社内情報・認証情報・API キーを HTML に埋め込まない。
  • 点滅・大音量・揺れがあるため、スタート画面で注意書きを出し、prefers-reduced-motion では演出を弱める。
  • 文体: 日本語、です・ます調。ナレーションは読み上げやすいよう、読点で区切り、数字は読み方を意識する（例: 「66パーセント」「1,096件」）。

7. LESSON（学び）の一覧

各クエストや節の終わりに、緑の「LESSON n」バナーを同じ見た目で出す（SE: pinpon）。

  1. 補助輪は、当時は正しかった。足りなかったのは外す基準（測る仕組み）。
  2. 無駄は、見えて初めて無駄になる。測る仕組みは、最初に入れる。
  3. 足場は 2 種類。「能力不足を補うもの」は外し、「能力に依存しないもの」は残す。
  4. 規則は、お願いではなく hook で強制する。設定だけでは守られない。
  5. 補助輪はゼロにせず、薄く、外から効く場所だけ残す。そして使い分ける。
  6. 再利用できるものは、データに分ける。価値の中心は顧客パック・出典・確度。

  • API キーはページのメモリにだけ保持し、保存・埋め込みしない。クラウド呼び出しが失敗したら、自動でブラウザー内蔵に切り替える。最新の提供状況（モデル名・リージョン）は実行時に Microsoft Learn で確認し、使えない場合は入力欄で変えられるようにする。

9. 演出・SE・BGM（すべて Web Audio で合成。外部音源なし）

  • テロップ: 太い縁取りのフチ文字。帯（黄／赤／水色）、スラム（巨大な数字・語が拡大して着地、画面揺れ・フラッシュ・集中線・粒子）、強調色（{y|…} 黄／{r|…} 赤／{c|…} 水色／{g|…} 緑）。
  • カメラ: CSS 3D（perspective＋translate3d）で、ドリー、オービット、ドリーズーム、円環の中心から見回す（視点を軸にした回転）、手持ち風の揺れ。
  • 画面効果: グリッチ（RGB ずれ）、シネマスコープの黒帯、赤いビネット、フィルムグレイン、星空とパースペクティブ・グリッドの背景。
  • ゲーム／TV 演出: クエスト導入バナー、CHALLENGE カード、判定スタンプ（CLEAR はファンファーレ）、「CONTINUE? 10→0」、自作ゲートが標準機能に置き換わる UNLOCKED、「再開してください」が流れるコメント、スターウォーズ風クロール。
  • SE（合成）: whoosh／boom／hit／tick／pop／ding／pinpon／buzz／scratch／riser／glitch／siren／stamp／heart／spark／fanfare／drum／beep／shrink／coin。
  • BGM（合成・ループ）: drone／tension／drive／epic／calm／outro の 6 ムード。場面の感情に合わせて切り替える。

12. 実装の指針（品質を担保する設計）

  • ナレーション主導のタイムライン: 各シーンは S オブジェクトに、S.N(text)（ビート）、S.at(t,fn)、S.tween(t,dur,fn,ease)、S.mv(el,t,dur,{x,y,z,o,s…},ease)、S.say／S.slam／S.lesson／S.wl（成否カード）／S.verdict（判定スタンプ）／S.chal／S.arch（アーキテクチャ図）／S.media／S.play／S.flood／S.hbar（横棒）／S.meter などを登録して作る。シーンの長さは、ビートの積算から自動で決める。
  • グラフの凡例・ラベルを隠さない（重要）: 横棒は 3D の箱ではなく平らな棒にし、ラベルと数値は棒の手前（z を前へ）に置く。縦棒（3D の箱）のラベルも手前へ出す。スタンプや字幕が数値に重ならない位置にする。
  • 3D の箱の面は .sub ラッパーで包み、preserve-3d の入れ子が崩れないようにする。
  • スタート画面は実際にクリックされてから音声を初期化する（自動再生ポリシー対策）。
  • 音声（ナレーション）の再生が止まって映像が進まなくなる事態を避けるため、上限時間（安全タイマー）を持つ。
  • 動画（.webm）は、シーンに入ったときに該当の位置（オフセット）から再生し、終わったら頭に戻して繰り返す。一時停止に連動する。

13. 検証（完了の条件。結果を必ず自分で確認すること）

  1. 構文: <script> の中身を一時ファイルへ出し、node --check。（PowerShell で JS を書き換えるときは $('#id') の $ が展開されるので、シングルクォートで書く。）
  2. 通し実行: ヘッドレスの Chromium（Playwright）で、全シーンの goto(i) と stepEngine() を時間いっぱい進め、pageerror と console.error が 0 件であること。フル版は全 27 シーン、SHORT 版は全 9 シーン（SHORTSCENES）。
  3. 画面の目視: シーンごとに ?s=&t=&pause=1 でスクリーンショットを撮り、コンタクトシートにして確認する。特に、(a) 横棒・縦棒グラフの凡例とラベルが隠れていない、(b) 3 つのアーキテクチャ図に文字の欠けや重なりがない、(c) 航海図から降下してトピックが現れる、(d) 判定スタンプと LESSON バナーが読める、(e) 動画（EABK Studio／BAS）が再生される。
  4. 音声: Web Speech とクラウド音声は、モック（SpeechSynthesis と fetch を差し替え）で、(i) 話し終わるまで映像が待つ、(ii) 次シーンへ自動遷移する、(iii) クラウド音声のリクエスト先とヘッダーが正しい、(iv) 失敗時にブラウザー音声へ切り替わる、を確認する。実際の声は聴けないので、聴いていないと報告に書く。
  5. 禁止事項の検査: HTML 内に USD／ドル／円の金額、API キー、顧客名がないこと（grep）。
  6. 長さ: フル版は約 16 分、SHORT 版は約 5 分（読み上げ速度で前後する）。
  7. 後片付け: 起動したサーバーを停止し、$env:TEMP の一時ファイルを削除し、git status が意図した変更だけであることを確認してコミットする。
