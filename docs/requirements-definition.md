## 1. 概要

### 1.1 事業背景

EABK は、要求定義から検証・実装・統合・報告までを run として継続実行する開発キットである。run の worktree と一時作業資産は処理を分離する一方、完了後に残り続けると利用者のディスクと作業一覧を圧迫する。早すぎる削除は診断・再開・未統合成果を失わせるため、統合済みの正常完了 run だけを、所有権を確認して清掃する。

### 1.2 目的

| ID | 目的 | 成功指標 | 測定方法 |
|---|---|---|---|
| G-004 | 正常完了した EABK run の一時資産だけを main 統合後に除去し、失敗した run の再開可能性と利用者・他 run の資産を保護する | 対象となる正常完了 run では AC-057〜AC-068 が pass し、対象外資産の削除が 0 件 | System Test の証跡、対象テスト、verify の終了コード、Git worktree 一覧、ファイルシステム、run-report を照合する |

### 1.3 事業妥当性の判定

根拠あり。完了済み run の資源回収と、失敗時の診断・再開資産の保持を同時に満たす。ただし実装時には、現在の main 統合前清掃を廃止または順序変更し、配布物とガイドを同時に更新することが条件である。

## 2. 対象と対象外

- 対象: EABK run が作成し、run の記録から所有権を確定できる pool worktree、作業ブランチ、統合ブランチ、run 固有の一時作業資産、および清掃の判定・報告。
- 対象: ローカル main へ自動統合できる run と、Windows を含む EABK 対応環境。
- 対象外: main への push、外部システム、利用者が作成した worktree・ブランチ、他 run の資産、所有権を確定できない資産。
- `run-report.md` は清掃の診断記録として保持し、既存の保持期間による別の清掃まで本要求の即時削除対象にしない。

## 3. 前提・制約

### 3.1 既定制約

- 本製品は Python スクリプト、Git 操作、Markdown の報告で動く CLI/バッチ型ツールであり、利用者が操作する画面を持たない（SRC-015、SRC-016）。このため、要求定義プロンプトの ui_policy-1（変更可能な画面レイアウト）と ui_policy-2（画面上のペルソナ別情報表現）は適用しない。
- main への push、外部システムの変更、デプロイは本依頼の対象外である（SRC-014）。
- 削除可否を証明できない資産は削除しない。清掃の網羅性よりデータ保護を優先する。

### 3.4 状態

| 対象エンティティ | 状態 | 遷移の条件 |
|---|---|---|
| EABK run | 実行中 | run が開始され、終了結果が確定していない |
| EABK run | 統合待ち | 結果が全件完了で、run-report と最終検証が完了し、main 統合前である |
| EABK run | 統合済み | main への取り込みと取り込み後検証が成功した |
| EABK run | 清掃済み | 統合済み run の所有資産について安全な清掃が完了した |
| EABK run | 保持 | 正常完了・main 統合・安全判定のいずれかを満たさず、診断または再開のため資産を残した |
| run 所有資産 | 使用中 | run の処理または診断・再開に必要である |
| run 所有資産 | 清掃候補 | 所有権、安全性、正常完了、main 統合後の条件をすべて満たす |

| ペルソナ | 業務 | 主要な判断 | 使うデータ | 判断の頻度と緊急度 | 役割 | 出典 |

## 5. 利用シナリオ

1. run は実装・検証・報告を終え、結果を確定する。
2. 正常完了の場合だけ統合ブランチを main に統合し、main 上で検証する。
3. 統合と検証が成功した場合だけ、当該 run の所有資産を列挙し、保護対象を除外して清掃する。
4. 途中失敗、blocked、中止、競合、検証失敗、所有権不明、未コミット変更がある場合は資産を保持し、理由を報告する。
5. 清掃が中断した場合は、残された診断情報から安全に再試行する。

## 6. 要求

### 6.1 機能要求

#### FR-1009 正常完了 run の統合後清掃
- 要求: EABK は、run が正常完了し、その成果を main に統合して統合後検証に成功した場合だけ、その run が作成した清掃候補を除去できる。
- 決定状態: 承認済み（依頼 2026-10-10）　出自: 依頼原文　優先度: MUST（統合前の成果喪失を防ぎながら完了後の資源を回収するため）
- 上位: G-004　出典: SRC-014
- 対象エンティティ: EABK run、run 所有資産　関係する状態: 統合待ち→統合済み→清掃済み、清掃候補→削除済み　参照パラメータ: なし
- 関連する既存資産: 共通部品「run 作業資産清掃」、共通部品「worktree pool 管理」、共通部品「conductor 終了契約」
- 受入基準 AC-057: 結果が「全件完了」で、完了条件、最終 verify、対象テスト、main 統合、main 統合後 verify、main の統合 commit と統合後検証結果を含む run-report の確定、finish がこの順に成功した run では、その後に限って pool worktree を含む当該 run 所有資産の清掃が開始される。
  - 検証レベル: system
- 受入基準 AC-058: blocked、中止、canary 失敗、完了条件未達、最終 verify または対象テスト失敗、main 統合の競合または失敗、main 統合後 verify 失敗、run-report 未確定、finish 失敗のいずれかでは、当該 run の pool worktree を含む worktree と一時作業資産が削除されず、EABK run は保持になる。
  - 検証レベル: system
- 受入基準 AC-059: 清掃が成功したとき、清掃候補となった当該 run の pool worktree、作業ブランチ、統合済みの統合ブランチ、一時作業資産は Git の登録とファイルシステムから除去され、main の統合結果は残る。
  - 検証レベル: integration

#### FR-1010 清掃の診断と再開
- 要求: EABK 利用者・運用者は、清掃の対象、実施結果、保持した資産と理由を run-report で確認し、清掃が中断しても残存資産から安全に再試行できる。
- 決定状態: 承認済み（依頼 2026-10-10）　出自: 依頼原文　優先度: MUST（誤削除の調査と途中失敗からの再開に必要なため）
- 上位: G-004　出典: SRC-014、SRC-015、SRC-016
- 対象エンティティ: EABK run、run 所有資産　関係する状態: 統合済み→清掃済み、統合済み→保持、使用中→清掃候補→削除済み、清掃候補→保護　参照パラメータ: なし
- 関連する既存資産: 共通部品「run 状態・完了記録」、共通部品「run 作業資産清掃」、共通部品「conductor 終了契約」、共通部品「run 運用ガイド」
- 受入基準 AC-060: main 統合後 verify の成功後、清掃を開始する前に、run-report に正常完了、main の統合 commit、main 統合後検証の結果、清掃候補、保護または保持する資産と理由が記録されて確定し、その後に finish、清掃の順で進む。清掃後は、run-report で各候補の削除・保持・失敗の結果が確認できる。
  - 検証レベル: system
- 受入基準 AC-061: いずれかの清掃操作が失敗した場合、EABK は失敗を成功として扱わず、以後の安全性を確認できない削除を停止し、main の統合結果、run-report、診断情報、未削除資産を保持して非 0 で終了する。
  - 検証レベル: integration
- 受入基準 AC-062: 一部の清掃後に再実行した場合、既に削除済みの当該 run 所有資産を成功済みとして扱い、残存する清掃候補だけを再評価し、他の資産を対象に広げずに完了できる。
  - 検証レベル: integration

### 6.2 非機能要求

#### NFR-OPS-005 所有権と保護状態にもとづく安全な削除
- 要求: EABK は、削除前に当該 run の記録、Git 登録、正規化したパス、作業ツリーの状態を照合し、所有権と安全性を証明できた run 所有資産だけを削除する。
- 決定状態: 承認済み（依頼 2026-10-10）　出自: 依頼原文　優先度: MUST（削除は取り消せず、他 run と利用者成果の損失を防ぐ必要があるため）
- 上位: G-004　出典: SRC-014、SRC-015、SRC-017
- 対象エンティティ: run 所有資産　関係する状態: 使用中→清掃候補→削除済み、使用中→保護、清掃候補→保護　参照パラメータ: なし
- 関連する既存資産: 共通部品「run 作業資産清掃」、共通部品「run 状態・完了記録」、共通部品「worktree pool 管理」
- 受入基準 AC-063: run-id、meta、queue、Git worktree 登録、ブランチ名、正規化した実体パスの対応がすべて当該 run を示す資産だけが清掃候補になり、一致しない、欠損する、または所有権が一意でない資産は理由付きで保護される。
  - 検証レベル: integration
- 受入基準 AC-064: 他 run の資産、利用者作成の worktree またはブランチ、未コミット変更を持つ worktree、リポジトリルート、main の worktree、実行中の作業ツリー、設定された保護対象を混在させた場合、それらは変更も削除もされず、当該 run の安全な候補だけが処理される。
  - 検証レベル: system
- 受入基準 AC-065: 実削除前の確認結果には清掃候補、保護対象、未コミット状態、実行予定の操作が示され、確認時点から状態が変化した候補は再検査で保護され、強制削除されない。
  - 検証レベル: integration

#### NFR-COMPAT-001 Windows・報告・配布文書の一貫性
- 要求: EABK の run 清掃は Windows を含む対応環境で同じ安全条件を満たし、run-report、カタログ、配布物、利用者ガイドが実際の清掃条件・順序・結果と一致する。
- 決定状態: 承認済み（依頼 2026-10-10）　出自: 依頼原文　優先度: MUST（主要な利用環境と配布後の利用者に同じ安全契約を提供するため）
- 上位: G-004　出典: SRC-014、SRC-016、SRC-018
- 対象エンティティ: EABK run、run 所有資産　関係する状態: 統合済み→清掃済み、統合済み→保持、清掃候補→削除済み、清掃候補→保護　参照パラメータ: なし
- 関連する既存資産: 共通部品「run 作業資産清掃」、共通部品「run 状態・完了記録」、共通部品「worktree pool 管理」、共通部品「conductor 終了契約」、共通部品「run 運用ガイド」、共通部品「配布同期対象」
- 受入基準 AC-066: Windows 上でドライブ文字の大小、区切り文字または絶対パス表記だけが異なり、ファイルシステム上の実体と Git 登録が同一である複数のパス表記は、同じ run 所有資産の表記揺れとして 1 候補に扱う。一方、正規化した文字列が同じでもファイルシステム上の実体、Git 登録または run の所有記録のいずれかが異なる入力は、異なる資産の衝突として双方を保護し、一方の判定で他方を削除しない。空白を含むパスでも同じ判定を行い、ファイルロック中の資産は削除せずに保持理由を報告する。
  - 検証レベル: system
- 受入基準 AC-067: 配布用の管理対象とインストール後の EABK に清掃機能と必要な実行契約が含まれ、カタログ、conductor の終了順序、run-report の項目、スクリプト参照、利用者ガイド、トラブルシューティングが「正常完了・main 統合後だけ清掃し、それ以外は保持する」という同じ内容を示す。
  - 検証レベル: system
- 受入基準 AC-068: 清掃前後の Git 状態を比較したとき、既存の無関係な変更と保護対象に差分がなく、清掃後に `python scripts/verify.py --docs-only`、最終 verify、および清掃対象テストがすべて exit 0 となる。
  - 検証レベル: system
