## 1. 概要

### 1.1 事業背景

EABK の要求定義書、カタログ、System Test 台帳、ID 台帳、実行履歴は、複数の人と AI エージェントが引き継いで開発するための管理データである。EABK Studio はその管理データを開かずに横断して読み、要求・実装・試験・履歴の対応と不足を把握できるローカル専用 Web アプリである。現状は管理データを個別に読む摩擦があり、目的に対する進捗、実装登録率、未回答、BLOCKED、出典、ソース対応の判断を一つの視点で行いにくい。

### 1.2 目的

| ID | 目的 | 成功指標 | 測定方法 |
|---|---|---|---|
| G-001 | 管理データの関係を読み取り、目的から要求・実装・試験までを一貫して確認できるようにする | ダッシュボード、地図、図式、表、ソース対応で同一 ID の関係を辿れる | AC-001〜AC-006、AC-021〜AC-024 を System Test で確認 |
| G-002 | Product Manager、Architect、Software Engineer が各自の判断に必要な表現を初期状態から得る | 3 ペルソナの既定表現と代替表現が要求・AC・出典で確認できる | AC-007〜AC-012、AC-025〜AC-027 |
| G-003 | 管理データの鮮度、整合性、未解決事項を安全な読取で可視化する | 自動再読込、フィンガープリント、未回答、BLOCKED、状態表示が確認できる | AC-013〜AC-020、AC-028〜AC-035 |

### 1.3 受益者・費用負担者・決定権者

受益者は上記 3 ペルソナと要求定義・実装・試験の担当者である。費用負担者と要求の最終決定権者は依頼に明示されておらず、Q-001 で確認する。事業妥当性は **条件付き** とする。既存のローカル専用・追加インストール不要・管理データ読取という実装事実（SRC-001〜SRC-003）により小さく始められるが、権限、保存単位、外部連携、証跡、アクセシビリティの判断が未回答であるため、共有運用への拡張は保留する。

## 2. 対象と対象外

**対象**: `docs/requirements-definition.md`、`docs/catalog.md`、`tests/system/ledger.json`、`docs/id-registry.md`、`docs/run-history.md` および `scripts/ebak.config.json` で指定された管理データの読取・解析・可視化、リポジトリ切替、検索、図式、配置、表、ソース対応、JA/EN 表示、更新検知。

**対象外**: 管理データへの書込み・自動修正、コード・テスト・設定の生成や変更、外部サービスへの接続、認証・認可の正本化、共同編集、利用者データの永続保存、外部公開、削除・移行など不可逆操作。これらを必要とする要求は Q-001〜Q-004 の回答まで BLOCKED とする。

## 3. 前提・制約

### 3.1 既定制約（要求定義プロンプトの常設方針）

- 利用者が複数コンポーネントの位置、分割、タブ化、表示/非表示、最大化、既定復元、キーボード代替を行える UI とする（方針は承認済み、具体化は NFR-UX-001〜005）。
- ペルソナごとに既定の情報表現を持ち、同じデータを別表現へ切り替えられ、視覚表現には表・テキスト・キーボード等の代替を持つ（方針は承認済み、具体化は FR-003〜FR-005、NFR-UX-006〜009）。
- Python 3.9 以上、追加インストールなし、127.0.0.1 のみで待ち受け、管理データ以外を読み書きしない（SRC-001〜SRC-003）。
- 対象リポジトリは `scripts/ebak.config.json` の `management_files` を正本とする（SRC-002）。
- 言語は日本語・英語。既定言語の決定は実装の JA 表示を現状契約として扱い、変更は Q-009 の対象外（利用者データ・権限に触れないため、変更しやすい実装細部）。

## 5. 利用シナリオ

1. 利用者は対象リポジトリを既定値で起動し、管理データを読込む。  
2. Product Manager はダッシュボードから目的・進捗・未回答・BLOCKED を選択し、2D マップまたは表へ移る。  
3. Architect は 2D/3D マップ、配置、図式で関係と層を確認する。  
4. Software Engineer は検索、表、ソース対応、状態遷移で要求から試験までを確認する。  
5. 読込中に管理データが更新された場合、利用者へ鮮度を示し再読込する。  
6. リポジトリ切替が入力不備または管理データ不足で失敗した場合、現在の表示を失わず原因と次の行動を示す。  
7. 支援への引継ぎは、ID、出典、状態、カタログのパスをテキストまたは CSV で共有する。認証付き共有や監査証跡は Q-001、Q-004 の回答待ち。
