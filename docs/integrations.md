# 外部連携カタログ

Studio が読み取る連携。INT-001 はローカルのファイル、INT-002 は GitHub の読み取り専用の取得です（どちらも書込みはしません）。

| ID | 名前 | 連携先 | 状態 | 関連する要求 |
|---|---|---|---|---|
| INT-001 | 指定リポジトリのローカル解析 | 利用者が選択したローカル Git リポジトリ | 運用中 | FR-1086、FR-1088 |
| INT-002 | GitHub の Issue・PR・Actions の読取り | 指定リポジトリの origin が指す GitHub | 運用中 | FR-1088、NFR-SEC-003 |

#### INT-001 指定リポジトリのローカル解析
- 連携先: 利用者が選択したローカル Git リポジトリ。ファイルと Git のオブジェクトが正本。
- 方向: 受信
- 備考: Studio のタスク編集は原本へ書き戻さない。
- 方式: ローカルファイルと Git の読取りコマンド。外部 API、fetch、コード実行は行わない。
- 頻度と量: 起動・切替・入力変更時に再解析。追跡済み・未追跡・初期化済みサブモジュールのファイルの内容を解析し、無視対象・生成物・未初期化のサブモジュールはパスだけを一覧にする（内容は読まない）。テキストのファイル単位の上限は {PARAM-062}。超過時も一覧と理由は表示。
- データ分類: 利用者が閲覧可能なローカルリポジトリの情報。Studio は機密区分を認定しない。
- 個人情報: ファイル本文・タスク・コミット件名に含まれる可能性がある。外部送信せず、コミットの氏名・メールアドレスは取得しない。
- 認証認可: OS のファイルアクセス権を使用。追加の資格情報は不要。認証情報らしいファイル名は本文解析から除外。
- 可用性・SLA: 外部 SLA なし。ローカルファイルと Git が利用可能であることが前提。
- レート制限: 外部 API を呼ばないため該当なし。
- エラー・再試行・冪等性: 読取り失敗・非対応・除外を診断に記録。Git の取得失敗は明示的なエラー。再読込で再試行し、タスク ID は出典・本文・同文の出現順から決定する。
- 契約・バージョン: Git の ls-files（--recurse-submodules・--ignored --directory を含む）、submodule status、log の出力、既存 EABK の管理データ、UTF-8 の対応テキスト。依存関係は package.json と requirements*.txt、import は Python と JS/TS の静的ローカルパスに限定。
- 変更通知: ファイルのパス・サイズ・更新時刻と Git の参照を更新検知に使用。
- 監視: --check と「リポジトリ分析・タスク管理」で件数・出典・解析診断を確認。
- データ保持: 解析モデルはメモリー内のみ。タスクの編集結果は Studio の専用保存先に保持し、Studio 作成タスクの削除・取込状態のリセットを利用者が明示操作する。
- 障害時の代替: 最後に表示したデータを保持し、失敗理由と再試行の手段を表示。タスク保存失敗では入力を保持。
- 責任分界: 原本の内容・OS のアクセス権・利用目的はリポジトリ管理者と利用者、解析結果と分離保存は Studio。
- 法務・ライセンス: 原本の利用権限は利用者が確認。ローカル閲覧だけを行い、第三者への再配布・外部提供は行わない。
- 状態: 運用中
- 関連する要求: FR-1086、FR-1088、NFR-SEC-002、NFR-SEC-003

#### INT-002 GitHub の Issue・PR・Actions の読取り
- 連携先: 指定リポジトリの origin（origin がなく remote が 1 つだけならそれ）が指す GitHub（github.com または GitHub Enterprise）。
- 方向: 受信
- 備考: 依頼 2026-11-12「全ての関連データを取得」による NFR-SEC-003 の外部連携の限定的な改訂（Q-002 A の例外。読取りだけ）。
- 方式: この端末にインストールされ認証済みの GitHub CLI（gh）の `issue list`・`pr list`・`run list` を `--json` で実行する。書込み系のコマンドは使わない。
- 頻度と量: 起動時と対象の切替時に裏で取得し、10 分を超えたら次の表示で再取得。画面の「GitHub から再取得」で即時に再取得。種別ごとの上限は環境変数 HVE_STUDIO_REMOTE_LIMIT（既定 10000 件）で、上限に達した種別は画面に表示する。3 種別は並行に取得し、終わった種別から表示する（実測: 本リポジトリで Issue・PR は 1 秒未満、Actions の実行 6,622 件は約 130 秒）。1 種別の待ち時間の上限は HVE_STUDIO_REMOTE_TIMEOUT（既定 600 秒）。
- データ分類: 利用者の GitHub 権限で閲覧可能な情報。Studio は機密区分を認定しない。
- 個人情報: Issue・PR の作成者・担当者のログイン名を含む。メールアドレスは取得しない。外部へ再送信しない。
- 認証認可: gh の既存の認証をそのまま使う。Studio はトークンを読まない・求めない・保存しない。
- 可用性・SLA: GitHub と gh に依存。取得できなくてもローカル解析（INT-001）は使える。
- レート制限: GitHub API のレート制限に従う。超過は種別ごとのエラーとして表示。
- エラー・再試行・冪等性: gh 未インストール・未認証・GitHub 以外の remote は「取得不可」と理由を表示。種別ごとの失敗は「一部取得」として理由を表示。再取得ボタンで再試行。Issue のタスク ID は `github:issue:<番号>`。
- 契約・バージョン: gh の `--json` 出力のフィールド名。
- 変更通知: なし（再取得の時点の内容）。
- 監視: 「リポジトリ分析・タスク管理」の GitHub の状態の行。
- データ保持: 取得結果はメモリー内のみ（ディスクに保存しない）。Issue の状態の上書きだけを FR-1088 のタスク保存先に保持。
- 障害時の代替: `--no-remote` で起動すると取得しない。
- 責任分界: GitHub の内容と権限は GitHub とリポジトリ管理者、取得と表示は Studio。
- 法務・ライセンス: 利用者の権限での閲覧だけ。第三者への再配布・外部提供は行わない。
- 状態: 運用中
- 関連する要求: FR-1088、NFR-SEC-003
