# 外部連携カタログ

Studio が読み取る連携。INT-001 はローカルのファイル、INT-002 は GitHub の読み取り専用の取得です（どちらも書込みはしません）。INT-003・INT-004 は、利用者が設定して明示的に開始する生成 AI の呼出しです（検討中。未実装）。

| ID | 名前 | 連携先 | 状態 | 関連する要求 |
|---|---|---|---|---|
| INT-001 | 指定リポジトリのローカル解析 | 利用者が選択したローカル Git リポジトリ | 運用中 | FR-1086、FR-1088、FR-1099、FR-1100 |
| INT-002 | GitHub の Issue・PR・Actions の読取り | 指定リポジトリの origin が指す GitHub | 運用中 | FR-1088、NFR-SEC-003 |
| INT-003 | Microsoft Azure の生成 AI（推論とリソースの一覧） | Azure OpenAI（Microsoft Foundry）と Azure Resource Manager | 検討中 | FR-1096、FR-1097、FR-1098、NFR-SEC-024 |
| INT-004 | GitHub Copilot SDK の生成 AI | Microsoft Copilot SDK（旧 GitHub Copilot SDK）のランタイムと、その先の GitHub Copilot または BYOK の提供元 | 検討中 | FR-1096、FR-1098、NFR-SEC-024 |

#### INT-001 指定リポジトリのローカル解析
- 連携先: 利用者が選択したローカル Git リポジトリ。ファイルと Git のオブジェクトが正本。FR-1099 の対象リポジトリ群では、選んだ各リポジトリを同じ方式で個別に読み、FR-1100 のリポジトリ間の関係もこの読取りの結果から作る（2026-11-20）。
- 方向: 受信
- 備考: Studio のタスク編集は原本へ書き戻さない。
- 方式: ローカルファイルと Git の読取りコマンド。外部 API、fetch、コード実行は行わない。
- 頻度と量: 起動・切替・入力変更時に再解析。追跡済み・未追跡・初期化済みサブモジュールのファイルの内容を解析し、無視対象・生成物・未初期化のサブモジュールはパスだけを一覧にする（内容は読まない）。テキストのファイル単位の上限は {PARAM-062}。超過時も一覧と理由は表示。
- データ分類: 利用者が閲覧可能なローカルリポジトリの情報。Studio は機密区分を認定しない。
- 個人情報: ファイル本文・タスク・コミット件名に含まれる可能性がある。外部送信せず、コミットの氏名・メールアドレスは取得しない。
- 認証認可: OS のファイルアクセス権を使用。追加の資格情報は不要。認証情報らしいファイル名は本文解析から除外。
- 可用性・SLA: 外部 SLA なし。ローカルファイルと Git が利用可能であることが前提。
- レート制限: 外部 API を呼ばないため該当なし。
- エラー・再試行・冪等性: 読取り失敗・非対応・除外を診断に記録。Git の取得失敗は明示的なエラー。再読込で再試行し、タスク ID は出典・本文・同文の出現順から決定する。
- 契約・バージョン: Git の ls-files（--recurse-submodules・--ignored --directory を含む）、submodule status、log の出力、既存 EABK の管理データ、UTF-8 の対応テキスト。依存関係は package.json と requirements*.txt、import は Python と JS/TS の静的ローカルパスに限定。
- 変更通知: ファイルのパス・サイズ・更新時刻と Git の参照を更新検知に使用。
- 監視: --check と「リポジトリ分析・タスク管理」で件数・出典・解析診断を確認。
- データ保持: 解析モデルはメモリー内のみ。タスクの編集結果は Studio の専用保存先に保持し、Studio 作成タスクの削除・取込状態のリセットを利用者が明示操作する。
- 障害時の代替: 最後に表示したデータを保持し、失敗理由と再試行の手段を表示。タスク保存失敗では入力を保持。
- 責任分界: 原本の内容・OS のアクセス権・利用目的はリポジトリ管理者と利用者、解析結果と分離保存は Studio。
- 法務・ライセンス: 原本の利用権限は利用者が確認。ローカル閲覧だけを行い、第三者への再配布・外部提供は行わない。
- 状態: 運用中
- 関連する要求: FR-1086、FR-1088、FR-1099、FR-1100、NFR-SEC-002、NFR-SEC-003

#### INT-002 GitHub の Issue・PR・Actions の読取り
- 連携先: 指定リポジトリの origin（origin がなく remote が 1 つだけならそれ）が指す GitHub（github.com または GitHub Enterprise）。
- 方向: 受信
- 備考: 依頼 2026-11-12「全ての関連データを取得」による NFR-SEC-003 の外部連携の限定的な改訂（Q-002 A の例外。読取りだけ）。
- 方式: この端末にインストールされ認証済みの GitHub CLI（gh）の `issue list`・`pr list`・`run list` を `--json` で実行する。書込み系のコマンドは使わない。
- 頻度と量: 起動時と対象の切替時に裏で取得し、10 分を超えたら次の表示で再取得。画面の「GitHub から再取得」で即時に再取得。種別ごとの上限は環境変数 HVE_STUDIO_REMOTE_LIMIT（既定 10000 件）で、上限に達した種別は画面に表示する。3 種別は並行に取得し、終わった種別から表示する（実測: 本リポジトリで Issue・PR は 1 秒未満、Actions の実行 6,622 件は約 130 秒）。1 種別の待ち時間の上限は HVE_STUDIO_REMOTE_TIMEOUT（既定 600 秒）。
- データ分類: 利用者の GitHub 権限で閲覧可能な情報。Studio は機密区分を認定しない。
- 個人情報: Issue・PR の作成者・担当者のログイン名を含む。メールアドレスは取得しない。外部へ再送信しない。
- 認証認可: gh の既存の認証をそのまま使う。この取得では Studio はトークンを読まない・求めない・保存しない（AI の呼出しで gh のトークンを SDK へ渡すのは INT-004 だけ）。`--no-remote` で起動したときは、この取得のために gh を実行しない（AI のための取得には適用しない）。
- 可用性・SLA: GitHub と gh に依存。取得できなくてもローカル解析（INT-001）は使える。
- レート制限: GitHub API のレート制限に従う。超過は種別ごとのエラーとして表示。
- エラー・再試行・冪等性: gh 未インストール・未認証・GitHub 以外の remote は「取得不可」と理由を表示。種別ごとの失敗は「一部取得」として理由を表示。再取得ボタンで再試行。Issue のタスク ID は `github:issue:<番号>`。
- 契約・バージョン: gh の `--json` 出力のフィールド名。
- 変更通知: なし（再取得の時点の内容）。
- 監視: 「リポジトリ分析・タスク管理」の GitHub の状態の行。
- データ保持: 取得結果はメモリー内のみ（ディスクに保存しない）。Issue の状態の上書きだけを FR-1088 のタスク保存先に保持。
- 障害時の代替: `--no-remote` で起動すると取得しない。
- 責任分界: GitHub の内容と権限は GitHub とリポジトリ管理者、取得と表示は Studio。
- 法務・ライセンス: 利用者の権限での閲覧だけ。第三者への再配布・外部提供は行わない。
- 状態: 運用中
- 関連する要求: FR-1088、NFR-SEC-003

#### INT-003 Microsoft Azure の生成 AI（推論とリソースの一覧）
- 連携先: 利用者が設定した Azure OpenAI（Microsoft Foundry）のリソースの推論エンドポイント。Entra ID 認証では、リソースの一覧のために Azure Resource Manager（management.azure.com）も読む。正本はそれぞれの Azure のサービス。
- 方向: 双方向
- 備考: 依頼 2026-11-20 による NFR-SEC-003 の外部連携の改訂（Q-002 A の例外）。利用者が設定し、操作したときだけ呼び出す。未設定では通信しない（NFR-SEC-024 AC-528）。推論は管理データの一部を送り回答を受け取る。Resource Manager は受信（一覧の読取り）だけ。
- 方式: HTTPS の REST（Azure OpenAI の推論 API。Resource Manager のサブスクリプション・Cognitive Services のアカウント・デプロイの一覧の読取り）。書込み系の Resource Manager の操作は使わない。
- 頻度と量: 利用者が「AI に聞く」を送るたびに 1 回の推論。リソースの一覧は設定画面を開いたときと再取得の操作のとき。1 回の応答の待ち時間の上限は {PARAM-068}。送る範囲は AC-530（Q-021 A）。
- データ分類: 対象リポジトリの管理データ（要求・受入基準・状態・決定記録など）。Studio は機密区分を認定しない。送る前に利用者が送り先と範囲を確認する（AC-530）。
- 個人情報: 管理データの本文に含まれる可能性がある。送るのは ID・題名・状態・受入基準の文・件数・リポジトリ名だけで、コードファイルの内容・ソース対応から取るファイルのパス・Issue と PR の本文は送らない（Q-021 A、AC-530）。サインインのアカウント名は画面に表示するだけで送らない。
- 認証認可: Key 認証（利用者が入力したキー。利用者が保存を選んだときだけ OS の資格情報の保管庫に保存し、削除できる。Q-020 B、AC-543・AC-544）または Microsoft Entra ID（この端末で既存のサインインから得る短時間のトークン。範囲は `https://cognitiveservices.azure.com/.default` と Resource Manager）。推論には Cognitive Services OpenAI User などの役割が要る（SRC-054）。Studio はパスワードを求めない。
- 可用性・SLA: Azure のサービスの SLA に従う。使えなくても AI 以外の機能は動く。
- レート制限: デプロイのクォータ（1 分あたりのトークン数・要求数）に従う。超過は原因として表示する。
- エラー・再試行・冪等性: 認証の失敗・権限不足・接続先なし・時間切れ・レート制限を区別して示す（AC-521・AC-524・AC-533）。自動では再試行せず、利用者のやり直しで再送する。推論は副作用がないため、やり直しは安全。
- 契約・バージョン: Azure OpenAI の推論 API の api-version と Resource Manager の api-version を設定または実装で固定する。具体値は実装時に決めてここに追記する（利用者の判断は不要な実装の細部）。
- 変更通知: なし。提供元のモデル・API の変更は Azure の告知に従う。
- 監視: 設定画面の「接続を確認」と、回答ごとの提供元・モデル名・時刻の表示。
- データ保持: Studio は回答をディスクに保存しない（AC-527）。送った内容の保持は Azure のサービスの規約とリソースの設定に従う（利用者が確認）。
- 障害時の代替: AI を使わずに、同じステップの画面で同じデータを確認できる。
- 責任分界: リソース・役割の割当て・費用・データの取扱いは Azure のサブスクリプションの管理者と利用者、呼出しと表示は Studio。
- 法務・ライセンス: 利用者の Azure の契約と、生成 AI の利用規約に従う。送るデータの社外への送信の可否は利用者の組織の規程による（Q-021）。
- 状態: 検討中
- 関連する要求: FR-1096、FR-1097、FR-1098、NFR-SEC-003、NFR-SEC-024

#### INT-004 GitHub Copilot SDK の生成 AI
- 連携先: Microsoft Copilot SDK（旧 GitHub Copilot SDK）のランタイムと、その先の GitHub Copilot のモデル、または BYOK で指定した提供元（OpenAI、Microsoft Foundry など）。正本はそれぞれの提供元。
- 方向: 双方向
- 備考: 依頼 2026-11-20 による NFR-SEC-003 の外部連携の改訂（Q-002 A の例外）。管理データの一部を送り、回答を受け取る。SDK の既定はツールの実行（ファイル編集など）を許すため、Studio はツールを無効にして、回答の文だけを使う（AC-527 の書込みなし）。
- 方式: Copilot SDK のクライアント（JSON-RPC でランタイムを呼ぶ）。SDK のパッケージが要る（SRC-053）。不足時は導入手順を示すだけで自動導入しない（11.3 の [ASSUMPTION]）。
- 頻度と量: 利用者が「AI に聞く」を送るたびに 1 回。1 回の応答の待ち時間の上限は {PARAM-068}。送る範囲は AC-530（Q-021 A）。
- データ分類: INT-003 と同じ。
- 個人情報: INT-003 と同じ。GitHub のアカウント名は画面に表示するだけで送らない。
- 認証認可: GitHub CLI のサインイン（端末で gh がサインイン済みの GitHub アカウント。GitHub Copilot の契約が要る）または Key（BYOK。提供元のキー。保存は INT-003 と同じ）。Q-022 A。SDK は gh の認証に対応するが優先順位が最下位のため（SRC-053、SRC-057）、Studio は呼出しのたびに実行時に `gh auth token` で取得したトークンを SDK へ明示的に渡し、環境変数のトークンや保存済みの Copilot CLI の認証情報へ切り替わらないようにする。トークンはメモリーだけで、保存しない。トークンのファイルは直接読まない。BYOK は Entra ID に対応しない（SRC-053）。INT-002 の「トークンを読まない」は Issue などの取得での gh の使い方で、AI の呼出しだけがトークンを SDK へ渡す。
- 可用性・SLA: GitHub Copilot または BYOK の提供元に依存。使えなくても AI 以外の機能は動く。
- レート制限: GitHub Copilot の利用量の上限、または BYOK の提供元のクォータに従う。超過は原因として表示する。
- エラー・再試行・冪等性: SDK の不足・未サインイン・契約なし・キーの誤り・時間切れを区別して示す。自動では再試行しない。
- 契約・バージョン: Copilot SDK のプロトコル版（sdk-protocol-version）とパッケージの版を実装時に固定し、ここに追記する（利用者の判断は不要な実装の細部）。
- 変更通知: SDK のリポジトリの CHANGELOG とリリース。GitHub Copilot SDK から Microsoft Copilot SDK への移行中（SRC-053）。
- 監視: 設定画面の「接続を確認」と、回答ごとの提供元・モデル名・時刻の表示。
- データ保持: Studio は回答をディスクに保存しない（AC-527）。送った内容の保持は GitHub Copilot または BYOK の提供元の規約に従う。
- 障害時の代替: AI を使わずに、同じステップの画面で同じデータを確認できる。
- 責任分界: 契約・利用量・課金は GitHub Copilot または提供元の契約者、呼出しと表示は Studio。
- 法務・ライセンス: SDK は MIT ライセンス。GitHub Copilot の利用規約、または BYOK の提供元の規約に従う。
- 状態: 検討中
- 関連する要求: FR-1096、FR-1098、NFR-SEC-003、NFR-SEC-024
