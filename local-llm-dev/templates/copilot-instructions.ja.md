# ローカル小型モデル向け 日本語 custom instructions テンプレート

`.github/copilot-instructions.md` として配置すると、VS Code の Chat / Agent の全リクエストに自動適用される。

> **このテンプレートの前提**
> ローカル小型モデル（4B〜20B）の日本語指示追従率は **74〜86%** である（実測: [TUTORIAL.md 付録 A](../TUTORIAL.md#付録-a-実測データと測定条件)）。
> クラウドの大規模モデルのように「書けば必ず守る」ことは期待できない。
> **ルールの 15〜25% は無視される前提**で、重要なものは検証ステップで機械的に確認する設計にすること。
>
> このテンプレートは実測に基づく次の 3 つの方針で書かれている。
> 1. **避けたい出力を具体的に名指しする**（肯定形 / 否定形のどちらが優れるかは実測で決着しなかった）
> 2. **1 ルール 1 文にする**（複数の要求を 1 行に詰め込まない）
> 3. **機械的に検証できる形式ルールを優先する**（守られたかどうかを後から確認できる）

---

## 使い方

1. 下の「テンプレート本体」を `.github/copilot-instructions.md` にコピーする
2. `{{ }}` の箇所を自分のプロジェクトに合わせて置き換える
3. 不要なセクションは削除する（**短いほど守られやすい**）

> インライン補完（Tab 補完）には custom instructions は適用されない（VS Code 公式仕様）。
> そもそもインライン補完はローカルモデルで動かせないため、オフライン構成では影響は限定的。

---

## テンプレート本体

> 下のブロックをそのまま `.github/copilot-instructions.md` へコピーする（外側の 4 つのバッククォートは含めない）。

````markdown
# プロジェクト共通ルール

## 応答のしかた

- 回答は日本語で書く。
- 英語で回答してはならない。
- コード内のコメントも日本語で書く。
- 結論を最初の 1 文で書く。
- コードは ```{{言語名}} で始まるコードフェンスの中に書く。

## 事実の扱い

- 確実に分かることだけを書く。
- 分からないことは「不明」と書く。
- ファイル名・API 名・オプション名は、実際に読んだ内容だけを書く。
- 出典が必要な記述には、参照したファイルのパスを添える。

## 変更のしかた

- 変更は依頼された範囲だけにとどめる。
- 既存のコードスタイルに合わせる。
- 変更したファイルと変更点を、作業の最後に一覧で示す。

## この環境の制約

- この環境はインターネットに接続していない。
- 提案するコマンドは、ローカルだけで完結するものにする。
- 依存パッケージの追加が必要な場合は、追加せずにその旨を伝える。

## 技術スタック

- 言語: {{言語とバージョン}}
- 主要ライブラリ: {{ライブラリ名}}
- テスト: {{テストコマンド}}
- ビルド: {{ビルドコマンド}}
````

## 書き方の指針（実測の根拠つき）

### 1. 肯定形か否定形かに時間を使わない

**どちらが優れるかは実測しても決着しなかった。**
5 モデル × 10 問 × 4 ルールで同じ内容を肯定形と否定形で書き分けて比較した結果、
**肯定形が平均 +3.0 pt** だったが、モデル別では +10 pt から **-15 pt**（qwen3:8b）までばらついた。

| モデル | 否定形 | 肯定形 | 差 |
|---|---|---|---|
| gpt-oss:20b | 85% | 89% | +4 pt |
| phi4-mini | 74% | 78% | +4 pt |
| qwen2.5:7b | 85% | 93% | +7 pt |
| qwen3:4b | 85% | 85% | ±0 |
| qwen3:8b | 89% | 89% | ±0 |

> **この差は信頼できない。** 同じ比較を指示文を修正する前に行ったときは
> **逆に否定形が 11 pt 優位**という結果だった。結論が符号ごと反転している。

### 2. むしろ重要なのは「別のルールの書き方」が影響すること

上の反転の原因を調べたところ、**別のルールを書き換えただけで、手をつけていない
ルールの追従率が大きく変わった**ことが分かった。

「英語で回答してはならない」という文は**一字も変えていない**のに、
同じシステムプロンプト内の**別の 2 ルールを書き換えただけ**で:

| | 修正前 | 修正後 |
|---|---|---|
| 「英語で回答してはならない」の遵守 | 46/50（92%） | **32/50（64%）** |
| 「回答は日本語で書く」の遵守（参考・文面も未変更） | 37/50（74%） | 37/50（74%） |

**28 pt 下がった。** ルールは独立に評価されないと考えた方がよい。

**実務上の指針**:

- 極性を悩むより、**避けたい出力を具体的に名指しする**ことに時間を使う。
  「簡潔に書く」より「1 文を 60 字以内にする」、「見出しを使わない」より「`#` で始まる行を書かない」。
- **ルールを 1 つ追加・修正したら、他のルールも含めて測り直す。** 差分だけを見てはいけない。
- 採用判断に使う値は、自分のルールとモデルで実測する。

> 上のテンプレート本体は、日本語ルールを肯定形と否定形の**両方**で書いている。
> どちらか一方が確実に優れるとは言えないためであり、
> **併記した場合の追従率は測定していない**（測定したのはどちらか一方だけを与えた場合）。

自分のルールで検証するには `tools/jp-eval` の `INSTR` スイートを使う。

```powershell
python jp_eval.py run --models <モデル名> --suites INSTR
python jp_eval.py score
```

### 3. 1 ルールは 1 文にする

VS Code 公式ドキュメントも「Keep your instructions short and self-contained. Each instruction should be a single, simple statement.」としている。

```markdown
<!-- 避ける: 1行に3つの要求が入っている -->
- 日本語で、見出しを使わず、コードにはコメントを付けて回答すること。

<!-- 使う -->
- 回答は日本語で書く。
- 本文は段落と箇条書きだけで構成する。
- コードには日本語のコメントを付ける。
```

### 4. 守られたか確認できるルールを優先する

| 守られやすい（機械的な形式） | 守られにくい（判断を伴う） |
|---|---|
| 決まった接頭辞を付ける | 見出しを使わない |
| 指定した言語のコードフェンスを使う | 簡潔に書く |
| 「不明」と書く | 適切に説明する |

実測では、定型の接頭辞は 5 モデル中 3 モデルが 10/10 で守った一方、
「見出しを使わない」は 6〜10/10 とばらついた。

> この接頭辞の値は **5 ルールでの別測定**によるもので、同梱の `tools/jp-eval`（4 ルール）では再現しない。

### 5. モデルサイズを考慮する

実測では **qwen3:4b が日本語指示にもかかわらず 10 問中 7 問を英語で回答**した一方、
同系列の qwen3:8b は 9/10 で日本語を維持した。

**日本語運用では 4B クラスは推奨しにくい。8B 以上を選ぶこと。**

---

## 適用されているか確認する

Chat ビューを右クリック →「Diagnostics」で、読み込まれた instruction ファイルと
エラーを確認できる（VS Code 公式機能）。

適用されない場合の確認点:

- ファイルが `.github/copilot-instructions.md` にあるか（`.github` フォルダ直下）
- `*.instructions.md` を使う場合、`applyTo` の glob が対象ファイルに一致しているか
- 設定 `chat.includeApplyingInstructions` が有効か

## ファイル種別の使い分け

| 種別 | 配置 | 適用範囲 |
|---|---|---|
| `.github/copilot-instructions.md` | `.github/` 直下 | ワークスペースの全リクエスト |
| `AGENTS.md` | ワークスペースルート | 全リクエスト。複数の AI エージェント共通で使う場合 |
| `.github/instructions/*.instructions.md` | `.github/instructions/` | `applyTo` の glob に一致するファイル作業時のみ |

優先順位は「個人 > リポジトリ > 組織」の順（VS Code 公式仕様）。

> **未検証の仮説**: 「適用されるルールが増えるほど追従率が下がる」という仮説はよく言われるが、
> **本レポートの実測では検証していない**（測定したのは 4 ルール固定の条件だけ）。
> ルール数と追従率の関係を知りたい場合は、`prompts.json` の `instruction_variants` に
> ルール数を変えたバリアントを追加して自分で測定すること。
